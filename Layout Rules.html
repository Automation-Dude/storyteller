Layout rules for a three-panel library

Nav sidebar · grid · detail panel — how to make them read as one calm surface instead of a pile of lines. Written to be applied directly in Storyteller's code.

01The separator budget

Every boundary between two regions gets exactly one separator: a tone change, or a hairline, or a gap + shadow. Never two. Most "too many lines" feelings come from boundaries paying twice — a border and a background change and each panel's own header border, all within a few pixels.

One boundary, one separator. Inside a panel, prefer spacing over lines.
  • Tone steps (recommended default) — each region is its own surface, zero borders. Quietest, and resize-friendly: a moving edge with no line on it can't look misaligned.
  • Hairlines — one shared background, a single 1px line per boundary. Then panel headers may not also have bottom borders; separate header from content with spacing only.
  • Floating panels — gaps + soft shadow over a sunk canvas. Most "modern app", but the gaps cost width; use 10px gaps max.

02The tone ladder

Three surfaces, always in the same order of importance. The panel you want the eye on is the lightest in light mode and the lightest in dark mode too — raised means lighter, both ways.

Keep the lightness steps small (0.015–0.035 in oklch). If a step is big enough to be "a color", it starts competing with the covers.

03The 56px header line

The single highest-leverage alignment rule: every panel's header row is exactly the same height (56px), with its content vertically centered. The grid toolbar, the detail panel's close row, and any list-panel header all share one invisible horizontal line across the whole app. When headers are 52px here and 64px there, every border you draw afterwards looks crooked even when it isn't.

04Spacing scale & insets

  • Scale: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 — nothing off-scale.
  • Panel inset = 24px on all sides of every panel's content (Tailwind p-6). One inset, everywhere — the left edge of the grid, the toolbar title, and the detail panel's text all sit 24px from their panel edge.
  • Grid gutter ≈ panel inset: 18–24px between cards. If the gutter is much smaller than the inset, the grid looks crowded inside a roomy frame.
  • Vertical rhythm inside the detail panel: 24–28px between sections, 8–12px within a section. Section labels (small caps + trailing hairline) are the only lines allowed inside a panel.

05Resizable panels

  • Detail panel: min 300px · default 384px · max min(720px, 45vw).
  • Handle: 14px invisible hit area straddling the edge; on hover/drag show a 4×44px rounded pill, accent-colored while dragging. Never an outline preview — the real panel moves.
  • Panel content is anchored to the panel's right edge with a fixed min-width: 300px, so text never reflows or squishes while the panel animates — it slides as one rigid sheet and gets revealed.
  • Snapping, if you keep it, is magnetic: within ~30px of a width where the grid gains/loses a column, ease the applied width toward that point (applied += (target − applied) × 0.32 per frame). No ghost lines, no jump on release.

06Motion spec — the panel/grid contract

The four wishes (panel animates, resize is smooth, grid doesn't jump, clicked card stays in view) are compatible if the grid never re-wraps without FLIP and never moves without a scroll anchor.

EventDurationEasing
Panel open / close360mscubic-bezier(0.22, 1, 0.36, 1)
Grid re-wrap (FLIP)240mssame
Hover / selection150–180msease

FLIP re-wrap — whenever the column count changes:

capture rects of cards near the viewport      // getBoundingClientRect
apply the new grid-template-columns
adjust scrollTop so the anchor card keeps its viewport Y   // see below
for each captured card:
  delta = oldRect − newRect
  card.animate([translate(delta), none], { 240ms, easeOut })

Scroll anchor — the clicked/selected card if it's on screen, else the topmost visible card. Measure with offsetTop (layout position — immune to running transforms), not getBoundingClientRect:

before: y = anchor.offsetTop − scroller.scrollTop
after:  scroller.scrollTop = anchor.offsetTop − y
  • During a continuous width change (drag or open animation), run the anchor correction every frame; run FLIP only at the moments the column count actually changes.
  • Only animate cards within ±700px of the viewport; farther cards may jump — nobody sees it. Use content-visibility: auto on cards so the 1000-card grid stays cheap.
  • Honor prefers-reduced-motion: skip FLIP and open/close animation, keep the scroll anchoring (it's a correctness feature, not a flourish).
